# Scopus Profiles MCP

سرور MCP با **۲۶ ابزار** برای داده‌های خود **Scopus**، با تمرکز بر پروفایل پژوهشگران، دانشگاه‌ها و سازمان‌ها؛ شامل وابستگی‌های سازمانی، آثار، همکاران، شاخص‌ها، مقایسه و خروجی کتاب‌شناختی. پیاده‌سازی مستقل با TypeScript و SDK رسمی MCP، همراه با `stdio` و `Streamable HTTP` است.

**کد این نرم‌افزار رایگان و دارای مجوز MIT است. دسترسی کامل و رایگان به همهٔ داده‌های Scopus تضمین نمی‌شود.** Elsevier برای API پروفایل‌ها کلید و مجوز مناسب می‌خواهد؛ داشتن کلید به‌تنهایی دسترسی همهٔ نماها یا شاخص‌ها را ایجاد نمی‌کند. [سیاست فعلی دسترسی Elsevier](https://dev.elsevier.com/) و [تنظیمات کلید و سهمیه](https://dev.elsevier.com/api_key_settings.html) مرجع این محدودیت‌اند.

این پروژه وابسته یا مورد تأیید Elsevier نیست. از Crossref، OpenAlex، Google Scholar یا پایگاه دیگر، داده‌ای به نام Scopus تولید نمی‌کند.

## نصب

پیش‌نیاز: **Node.js 24**، دسترسی شبکه به `api.elsevier.com` و برای داده‌های پروفایل، کلید مجاز Elsevier.

```sh
git clone https://github.com/Hhhkarimi/Hossein-Karimi-AI-Library.git
cd Hossein-Karimi-AI-Library/mcp/scopus-mcp
npm ci --ignore-scripts
npm run build
npm test
```

در PowerShell اگر `npm.ps1` محدود است، از `npm.cmd` استفاده کنید.

## تنظیم دسترسی

کلید را از [درگاه رسمی Elsevier](https://dev.elsevier.com/) و بر اساس دسترسی سازمان یا مجوز خود دریافت کنید. فایل خصوصی‌ای مانند `C:/private/scopus.env` بسازید:

```dotenv
ELSEVIER_API_KEY=YOUR_AUTHORIZED_KEY
# فقط اگر Elsevier توکن سازمانی در اختیار شما گذاشته است:
ELSEVIER_INST_TOKEN=
```

این مقادیر را وارد فایل‌های عمومی گیت‌هاب یا پیام‌های MCP نکنید. فایل `.env.example` فقط قالب است. برنامه فایل `.env` را خودکار نمی‌خواند؛ باید از محیط یا گزینهٔ داخلی Node یعنی `--env-file` استفاده کنید.

اگر سازمان شما بر پایهٔ IP مجوز می‌دهد، سرور را در شبکهٔ مجاز همان سازمان اجرا کنید. برای دسترسی راه دور، فقط توکن سازمانی صادرشده برای خودتان را تنظیم کنید. [روش‌های احراز هویت API](https://dev.elsevier.com/tecdoc_api_authentication.html) جزئیات را توضیح می‌دهد.

### اتصال محلی با stdio

در تنظیمات کلاینت MCP:

```json
{
  "mcpServers": {
    "scopus": {
      "command": "node",
      "args": [
        "--env-file=C:/private/scopus.env",
        "C:/path/to/Hossein-Karimi-AI-Library/mcp/scopus-mcp/dist/stdio.js"
      ]
    }
  }
}
```

مسیرها را با مسیر واقعی دستگاه خود جایگزین کنید. برای محیط Linux/macOS از مسیر مطلق همان سیستم استفاده کنید. اگر کلید از پیش در محیط کلاینت تعریف شده، گزینهٔ `--env-file` لازم نیست. stdout سرور فقط پیام‌های پروتکل است؛ در تنظیمات کلاینت، `node` را مستقیم اجرا کنید.

### اتصال HTTP

```sh
node --env-file=C:/private/scopus.env dist/http.js
```

پس از اجرای فرمان، نشانی اتصال محلی `http://127.0.0.1:8790/mcp` و مسیر وضعیت `/health` است. [نمونهٔ تنظیم HTTP](examples/mcp.http.json) همراه پروژه است. کلاینت‌های جدید و نسخهٔ پروتکل `2025-11-25` پشتیبانی می‌شوند؛ قالب پاسخ بسته به پروتکل می‌تواند JSON یا SSE باشد.

## دادهٔ گزارش‌نشده با دادهٔ ناموجود یکی نیست

سرور خطای مجوز، نداشتن کلید یا حذف یک فیلد از پاسخ را به معنی نبودن آن داده تعبیر نمی‌کند:

| وضعیت | معنی |
|---|---|
| مقدار عددی همراه با `reported` | مقدار صریحاً توسط Scopus گزارش شده است؛ صفر هم مقدار معتبر است |
| `not_returned` / `not_returned_in_view` | فیلد در پاسخ دریافتی نیامده؛ وجود یا عدم وجود آن تعیین نشده است |
| `ACCESS_DENIED` | API یا نمای درخواست‌شده برای دسترسی فعلی مجاز نیست |
| `SCOPUS_API_KEY_REQUIRED` | کلید محلی تنظیم نشده؛ دربارهٔ وجود داده نتیجه‌گیری نمی‌شود |
| `AUTHENTICATION_FAILED` | Elsevier اعتبارنامه را رد کرده است |
| `NOT_FOUND` | API برای این درخواست HTTP 404 داده؛ رکوردی در پاسخ برنگشته است |
| `not_attempted` | به علت خطای قبلی یا محدودیت زمان، درخواست هنوز انجام نشده است |

خطاهای ابزار دارای `data_absence_confirmed: false` هستند. یک جست‌وجوی معتبر با شمارش صفر صرفاً نبودن نتیجه برای **همان query و همان زمان** را نشان می‌دهد.

در `author_profile` و `author_metrics` حالت `AUTO` ابتدا نمای `ENHANCED` را می‌خواند؛ فقط پس از خطای مشخصِ مجوز، `STANDARD` و سپس `LIGHT` را امتحان می‌کند. اگر شاخص‌ها در پاسخ موفق کامل نباشند، نمای `METRICS` نیز بررسی می‌شود. `view_attempts` و `view_observations` تمام تلاش‌ها و زمان‌ها را نگه می‌دارند. در درخواست نمای صریح، تغییر نما پنهانی انجام نمی‌شود.

برای دانشگاه، `AUTO` نمای `STANDARD` و در صورت رد مجوز `LIGHT` را بررسی می‌کند. از تعداد آثارِ یک صفحه، شاخص دانشگاهی یا مجموع استنادهای دانشگاه ساخته نمی‌شود. اگر API مقدار موردنظر را ندهد، دلیل دسترسی/گزارش‌نشدن مشخص است و مقدار حدس زده نمی‌شود.

## دقت و دامنهٔ داده

- منبع تمام رکوردهای شبکه، API رسمی `api.elsevier.com` است. لینک‌های پروفایل Scopus همراه شناسه برمی‌گردند.
- `fetched_at` زمان دریافت پاسخ به UTC است؛ زمان آخرین به‌روزرسانی داخلی پایگاه Scopus را تضمین نمی‌کند. cache حداکثر ۶۰ ثانیه است.
- `citation_count` تعداد استنادها و `citing_document_count` تعداد اسناد استناددهنده‌اند؛ این دو یکی نیستند. شاخص‌ها ممکن است خوداستنادی را شامل شوند.
- h-index از مقدار گزارش‌شدهٔ پروفایل گرفته می‌شود؛ از تعداد محدودی مقاله محاسبه نمی‌شود.
- query نویسنده با `AF-ID` می‌تواند وابستگی تاریخی را هم در بر بگیرد. فهرست حاصل، فهرست کارکنان فعلی دانشگاه نیست.
- ادغام/اصلاح پروفایل می‌تواند شناسهٔ حل‌شده را تغییر دهد؛ `resolved_to_different_id` این موضوع را مشخص می‌کند. دادهٔ دو شناسهٔ حل‌شدهٔ متفاوت بین نماها پنهانی ادغام نمی‌شود.
- شمارش سالانه از total همان query در همان سال گرفته می‌شود. شمارش اسناد چند سازمان لزوماً جمع‌پذیر نیست، چون یک مقاله می‌تواند چند وابستگی داشته باشد.
- فهرست‌ها و متن‌ها برای اندازهٔ مناسب پاسخ MCP محدودند: نتایج جست‌وجو ۲۵ مورد، نام‌های جایگزین ۳۰، حوزه‌ها ۶۰ و نویسندگان مقاله ۱۰۰ مورد. صفحه‌بندی را برای جست‌وجو ادامه دهید. جزئیات سقف‌ها در مرجع ابزارها آمده است.
- مقدار شاخص نشریه با **سال گزارش‌شدهٔ همان شاخص** ارائه می‌شود؛ سال جاری برای مقدار قدیمی ساخته نمی‌شود.

Scopus امکانات عمومی محدودی هم به‌صورت [Scopus Preview](https://www.elsevier.support/scopus/answer/what-is-scopus-preview) دارد. وجود صفحهٔ عمومی به معنی دسترسی برنامه‌ای به همهٔ داده‌های آن نیست. در بررسی این نسخه، صفحات عمومی پروفایل از محیط ساخت قابل دریافت نبودند و API پروفایل بدون کلید `401` داد. این نتیجه، رد وجود پروفایل نیست. دادهٔ قدیمیِ اسکرین‌شات‌ها یا cache جست‌وجو به‌عنوان آمار زنده جایگزین نمی‌شود.

## آزمون‌ها

```sh
npm test
npm run verify:live
```

آزمون اول بدون شبکه و با دادهٔ مصنوعی اجرا می‌شود؛ همهٔ ۲۶ ابزار را از طریق کلاینت رسمی MCP بررسی می‌کند. parserها علاوه بر آن با نمونه‌های مستندات رسمی تطبیق داده شده‌اند. نمونه‌های مستندات، دادهٔ زندهٔ پروفایل تلقی نمی‌شوند.

آزمون زنده، اتصال HTTP واقعی و طبقه‌بندی موضوعی را می‌خواند. **بدون کلید، بررسی پروفایل‌ها اجرا نمی‌شود و این موضوع در گزارش صریح است.** برای آزمون زندهٔ پروفایل‌ها:

```sh
node --env-file=C:/private/scopus.env scripts/verify-live.mjs
```

متغیرهای اختیاری `SCOPUS_TEST_AUTHOR_ID` و `SCOPUS_TEST_AFFILIATION_ID` شناسه‌های آزمون را تعیین می‌کنند. اگر تعیین نشوند، از شناسه‌های مثال رسمی Elsevier استفاده می‌شود. `--full` درخواست‌های بیشتری برای آثار، همکاران، ارجاعات و روند سالانه می‌فرستد و به مجوزهای بیشتری نیاز دارد. `--stdio` همان بررسی را از مسیر اجرای واقعی stdio انجام می‌دهد. `VERIFY_REPORT` مسیر ذخیرهٔ گزارش JSON است.

برای سرور دیگری `MCP_URL` و در صورت نیاز `MCP_TOKEN` را در محیط تنظیم کنید. آزمون زنده فقط بررسی‌های نام‌برده در گزارش را تأیید می‌کند. [گزارش بررسی این نسخه](docs/VERIFICATION.md) تفاوت آزمون مصنوعی، نمونهٔ رسمی و آزمون زنده را ثبت کرده است.

## استقرار HTTP و Docker

اجرای محلی، به‌ویژه در شبکهٔ سازمان مجاز، نقطهٔ شروع مناسب است. برای bind خارج از loopback، `HOST`، `PUBLIC_URL` و `MCP_TOKEN` لازم‌اند:

```dotenv
HOST=0.0.0.0
PORT=8790
PUBLIC_URL=https://scopus-mcp.example.com
MCP_TOKEN=YOUR_RANDOM_SERVER_SECRET_AT_LEAST_24_CHARACTERS
```

TLS را reverse proxy خاتمه دهد و هدر Host عمومی را حفظ کند. کلاینت راه دور باید `Authorization: Bearer <MCP_TOKEN>` بفرستد. این secret مربوط به سرور MCP شماست و با کلید Elsevier تفاوت دارد. همهٔ کاربران مجاز این سرور، کلید و سهمیهٔ همان سرور را مصرف می‌کنند.

```sh
docker build -t scopus-mcp .
```

متغیرها را هنگام اجرا از محیط یا سامانهٔ secrets خود تزریق کنید. ساخت image در محیط تحویل آزموده نشده است. این پروژه روی سرویس ابری منتشر نشده و انتشار کد در گیت‌هاب به معنی ایجاد endpoint زنده نیست.

## رفتار فنی

فقط GET روی مسیرهای مشخص Scopus مجاز است. کلید و توکن فقط در header فرستاده می‌شوند؛ به URL، خروجی ابزار و log برنامه وارد نمی‌شوند. Redirect دنبال نمی‌شود. مسیر خرید، تغییر پروفایل یا دادهٔ حساب شخصی در ابزارها وجود ندارد.

حداکثر یک درخواست upstream هم‌زمان در هر process، فاصلهٔ شروع ۶۰۰ میلی‌ثانیه، timeout دوازده‌ثانیه‌ای برای دریافت بدنه، حداکثر یک retry برای خطای موقت شبکه/5xx، صف ۲۴ درخواست متمایز و cache حافظه با سقف ۸ مگابایتِ بدنهٔ JSON وجود دارد. بدنهٔ پاسخ upstream حداکثر ۵ مگابایت و بدنهٔ درخواست HTTP حداکثر ۶۴ کیلوبایت است. پاسخ 401 تکرار نمی‌شود؛ 403 فقط می‌تواند تلاش محدود برای نمای رسمی دیگری در حالت AUTO را فعال کند. 429 مهلت انتظار همان API را ثبت می‌کند.

گزارش سهمیه از headerهای آخرین پاسخ هر API گرفته می‌شود و حدس زده نمی‌شود. متادیتای cache، متن و لینک‌های دریافتی کوتاه‌مدت در حافظه می‌مانند؛ سرور پایگاه داده یا ثبت پایدار query ندارد. میزبان و reverse proxy می‌توانند logging جداگانه داشته باشند. درخواست گروهی/روند سالانه پس از حد زمان یا رد دسترسی، موارد انجام‌نشده را روشن گزارش می‌کند.

مجوز MIT شامل **کد** است؛ حقوق داده‌های دریافتی تابع مجوز و شرایط Elsevier باقی می‌ماند. [منابع و قراردادهای upstream](docs/SOURCES.md) و [فایل مجوز](LICENSE) همراه پروژه‌اند.
