# Upstream contract observations

Checked against the live public Torob web API on **2026-10-15**. This is an independent adapter to an undocumented interface, not an official Torob API integration.

| Public GET path on `https://api.torob.com` | Observed parameters / response |
| --- | --- |
| `/v4/base-product/search/` | `q`, `category`, `brand`, `page`, `size`, `sort`, `price__gt`, `price__lt`; `results`, `count`, `next`, `categories`, `attributes` |
| `/suggestion2/` | `q`; array of `{text}` |
| `/v4/base-product/details/` | `prk` product UUID; common card plus `products_info`, `products_in_store_info`, `key_specs`, `structural_specs` |
| `/v4/base-product/sellers/` | Parameters from the same product's `sellers_url`; `{results,count}` |
| `/v4/base-product/similar-base-product/` | `prk`, `limit`; product listing |

The official [Torob website](https://torob.com/) and its publicly served web-client scripts were inspected to confirm parameter names. In particular, the price filters are `price__gt` / `price__lt`; superficially plausible `price__gte` / `price__lte` parameters were ignored in a probe and are not used. Sort values observed/tested were `popularity`, `price`, `-price`.

Search may inject an ad in addition to requested `size`; it may match neighboring products and accessories. The adapter caps output, excludes ads by default and flags missing literal query terms. The API can return inconsistent counts/ranges, so totals are estimates and freshness is attached to every response, not assumed.

Observed numeric prices matched the accompanying Persian **تومان** text directly. No rial conversion is applied. Online offer rows include `availability`, `shop_name`, `shop_id`, `price`, `shop_score`/`score_info`, `name2`, `last_price_change_date`, and `is_price_unreliable`. Offline rows may have no availability flag. Product and offer IDs are different UUIDs.

Seller URLs can contain transient identifiers generated by Torob. They remain in memory during the short response cache; they are not written to disk by the adapter. Buy/contact redirect URLs are returned as links or omitted for offline contacts, never fetched by the server. No endpoint paths for accounts, payments or interaction logging are allowed.

No verified public price-history or buyer-review contract is included in this release. Do not add guessed endpoints as working tools. Re-run `npm run verify:live` after upstream changes and update fixtures if the verified response contract changes.

Protocol reference: [official MCP TypeScript SDK](https://github.com/modelcontextprotocol/typescript-sdk). The architectural inspiration is the public documentation of [mmdju/digikala-mcp](https://github.com/mmdju/digikala-mcp); its server implementation was unavailable and has not been copied.
