# Torob MCP — سرور MCP ترب

سرور مستقل و غیررسمی برای جست‌وجوی کالا، مشاهدهٔ قیمت و فروشندگان و مقایسهٔ محصولات ترب؛ با TypeScript، SDK رسمی MCP، اتصال محلی `stdio` و اتصال `Streamable HTTP`.

این پروژه از تجربهٔ استفادهٔ [digikala-mcp](https://github.com/mmdju/digikala-mcp) الهام گرفته است. مخزن مذکور کد سرور را منتشر نمی‌کند؛ کد این پروژه مستقل نوشته شده است. این پروژه وابسته یا مورد تأیید ترب نیست.

## شروع سریع

پیش‌نیاز: **Node.js 24** و دسترسی شبکه به `api.torob.com`. اجرای سرور به کلید API ترب نیاز ندارد.

مخزن را دریافت کنید و وارد پوشهٔ پروژه شوید:

```sh
git clone https://github.com/Hhhkarimi/Hossein-Karimi-AI-Library.git
cd Hossein-Karimi-AI-Library/mcp/torob-mcp
```

سپس اجرا کنید:

```sh
npm ci --ignore-scripts
npm run build
npm test
```

در PowerShell اگر اجرای `npm.ps1` محدود است، به‌جای `npm` از `npm.cmd` استفاده کنید.

### اتصال محلی با stdio

در تنظیمات کلاینت MCP خود، مسیر `dist/stdio.js` را مطلق وارد کنید:

```json
{
  "mcpServers": {
    "torob": {
      "command": "node",
      "args": ["C:/path/to/torob-mcp/dist/stdio.js"]
    }
  }
}
```

در فایل [examples/mcp.local.json](examples/mcp.local.json)، مسیر نمونه را با مسیر مطلق پوشهٔ پروژه روی دستگاه خود جایگزین کنید.

فرمان واقعی اجرای سرور `node dist/stdio.js` است. برای تنظیم کلاینت، همین فرمان را استفاده کنید؛ پیام‌های معمول `npm start` ممکن است وارد کانال stdout شوند. خروجی stdout سرور فقط پیام‌های MCP است.

### اتصال HTTP

```sh
npm run start:http
```

نشانی اتصال پس از اجرای فرمان: `http://127.0.0.1:8787/mcp`؛ وضعیت سرور: `http://127.0.0.1:8787/health`.

```json
{
  "mcpServers": {
    "torob": { "url": "http://127.0.0.1:8787/mcp" }
  }
}
```

در حالت پیش‌فرض سرور فقط روی loopback گوش می‌دهد. پشتیبانی HTTP شامل کلاینت‌های جدید و سازگار با پروتکل ۲۰۲۵ است؛ بسته به نسخهٔ کلاینت، پاسخ می‌تواند JSON یا SSE باشد.

## ابزارها

| ابزار | کاربرد |
| --- | --- |
| `search_torob` | جست‌وجوی فارسی/انگلیسی، صفحه‌بندی، مرتب‌سازی و فیلتر قیمت، دسته و برند |
| `torob_suggest` | پیشنهاد عبارت جست‌وجو از خود ترب |
| `search_filters` | کشف شناسهٔ دسته و برند، ویژگی‌ها و بازهٔ تخمینی قیمت |
| `browse_category` | مرور کالاها و مسیر دسته‌بندی |
| `product_details` | مشخصات، وضعیت کالا، قیمت و پیش‌نمایش محدود فروشندگان |
| `product_sellers` | پیشنهادهای فروشندگان اینترنتی یا حضوری، قیمت، امتیاز فروشگاه و شرایط |
| `similar_products` | محصولات مشابه پیشنهادی ترب |
| `get_products_batch` | دریافت جزئیات حداکثر ۱۰ محصول همراه با خطای مستقل هر مورد |
| `compare_products` | مقایسهٔ ۲ تا ۵ محصول و نمایش مشخصات متفاوت |
| `find_cheapest` | اسکن حداکثر ۳ صفحه، حذف تکراری‌ها و مرتب‌سازی کمترین قیمت‌های مشاهده‌شده |

نمونهٔ ورودی:

```json
{
  "name": "search_torob",
  "arguments": {
    "query": "سامسونگ a56",
    "max_price_toman": 150000000,
    "category_id": 94,
    "sort": "price_asc",
    "limit": 5
  }
}
```

بودجهٔ بالا صرفاً نمونهٔ نحو است. شناسه‌های دسته و برند را از پاسخ ابزارها بگیرید. برای دریافت جزئیات، شناسهٔ `id` یا لینک `https://torob.com/p/<UUID>/` را در پارامتر `product` بدهید. [مرجع پارامترها](docs/TOOLS.md) و [نمونهٔ مکالمه‌ها](examples/sample-calls.md) جزئیات بیشتری دارند.

## خواندن درست پاسخ‌ها

- قیمت عددی مستقیماً با واحد **تومان** برمی‌گردد؛ به ۱۰ تقسیم نمی‌شود. `price_unit` برابر `toman` است؛ برچسب رایج `IRT` کد رسمی ISO نیست.
- `fetched_at` زمان دریافت پاسخ از ترب به UTC است؛ `last_price_change_text` زمان تغییر قیمت اعلام‌شده از طرف فروشگاه است. این دو متفاوت‌اند.
- cache پاسخ‌ها ۶۰ ثانیه است. `cached` و `cache_expires_at` وضعیت و مهلت آن را مشخص می‌کنند.
- نتایج تبلیغاتی به‌صورت پیش‌فرض حذف می‌شوند. تعداد خروجی ممکن است کمتر از `limit` باشد. پارامتر `include_ads` این رفتار را تغییر می‌دهد.
- `condition_text`، عنوان، توضیحات گارانتی و پرچم `torob_is_authentic` را بررسی کنید. پرچم اصالت صرفاً دادهٔ ترب است؛ تأیید مستقل اصالت انجام نمی‌شود.
- ترب ممکن است نتایج مشابه یا دارای تطابق جزئی برگرداند. `low_confidence` و `unmatched_terms` بر اساس وجود واژه‌ها در عنوان فارسی/انگلیسی محاسبه می‌شوند؛ این یک معیار ساده است.
- بودجه روی نتایج پاسخ هم بررسی می‌شود. فیلتر دسته و برند به ترب ارسال می‌شود و بر اساس طبقه‌بندی خود ترب است.
- `total_estimate` تخمین ترب است. نتایج زنده و صفحه‌بندی آن می‌توانند جابه‌جا شوند. `find_cheapest` کمترین قیمت در صفحات بررسی‌شده را می‌دهد و تضمین ارزان‌ترین قیمت کل بازار نیست.
- قیمت فروشندگان هزینهٔ ارسال را شامل نمی‌شود. `price_unreliable`، وضعیت کارکرده، رجیستری، گارانتی و قدمت قیمت را بررسی کنید.
- `shop_score` امتیاز **فروشگاه** است. آن را به امتیاز خریداران محصول تعبیر نکنید. هر فروشگاه می‌تواند چند پیشنهاد داشته باشد.
- `loaded_list_complete` کامل‌بودن بارگذاری در مقایسه با شمارش همان پاسخ ترب را نشان می‌دهد. `truncated` یعنی فهرست خروجی با سقف درخواستی کوتاه شده است. این دو مستقل‌اند.
- مشخصات از `key_specs` و `structural_specs` با برچسب منبع نگه داشته می‌شوند؛ ممکن است داده‌های ترب با یکدیگر اختلاف داشته باشند. مقدار ناموجود `null` است.

تاریخچهٔ قیمت، نظرات خریداران، ورود به حساب و ثبت سفارش در این نسخه پیاده‌سازی نشده‌اند.

## آزمون و بازتولید

```sh
npm test
npm run verify:live
```

اولی بدون اینترنت از داده‌های مصنوعی استفاده می‌کند. دومی یک HTTP listener موقت ایجاد می‌کند، با کلاینت رسمی MCP متصل می‌شود و تمام ۱۰ ابزار را با **API زندهٔ ترب** اجرا می‌کند. این بررسی چند درخواست واقعی می‌فرستد و پس از پایان سرور را می‌بندد.

برای آزمون سرور منتشرشده در PowerShell:

```powershell
$env:MCP_URL = 'https://your-server.example/mcp'
$env:MCP_TOKEN = '<your-secret>'
npm run verify:live
```

برای آزمون واقعی stdio: `node scripts/verify-live.mjs --stdio`. متغیر `TOROB_TEST_QUERY` عبارت آزمون را تغییر می‌دهد؛ `VERIFY_REPORT` مسیر ذخیرهٔ گزارش JSON است. آزمون زنده به تغییرات موجودی، شبکه و محدودیت‌های ترب حساس است. [گزارش بررسی این نسخه](docs/VERIFICATION.md) همراه پروژه است.

## استقرار

### Cloudflare Workers

ورودی `src/worker.ts` و تنظیمات `wrangler.jsonc` آماده‌اند. این نسخه bundle شده و handler آن در Node آزموده شده، اما هنوز در runtime واقعی Cloudflare اجرا نشده است.

```sh
npx wrangler login
npx wrangler secret put MCP_TOKEN
npx wrangler deploy
```

در مرحلهٔ secret یک مقدار تصادفی حداقل ۲۴ نویسه‌ای وارد کنید. Worker بدون secret پاسخ 503 می‌دهد و درخواست‌های `/mcp` به `Authorization: Bearer <secret>` نیاز دارند. این secret متعلق به سرور شماست و کلید API ترب نیست. نشانی واقعی پس از deploy از خروجی Wrangler دریافت می‌شود. [راهنمای secrets کلادفلر](https://developers.cloudflare.com/workers/configuration/secrets/) مرجع تنظیم کلید است.

پیش از استفادهٔ مستمر، آزمون زنده را با `MCP_URL` همان استقرار اجرا کنید. دسترسی به ترب از منطقه یا IP میزبان ممکن است متفاوت باشد. cache و فاصله‌گذاری درخواست‌ها در هر process/Worker isolate برقرار است؛ محدودکنندهٔ مشترک در چند منطقه نیست.

### Node یا Docker

برای اتصال خارج از loopback، سه متغیر `HOST`، `PUBLIC_URL` و `MCP_TOKEN` لازم‌اند؛ TLS را reverse proxy خاتمه دهد و هدر Host عمومی را حفظ کند:

```powershell
$env:HOST = '0.0.0.0'
$env:PUBLIC_URL = 'https://mcp.example.com'
$env:MCP_TOKEN = '<at-least-24-random-characters>'
npm run start:http
```

فایل `Dockerfile` نیز همراه پروژه است. نمونهٔ ساخت: `docker build -t torob-mcp .`؛ هنگام اجرا `PUBLIC_URL` و `MCP_TOKEN` را از محیط یا سامانهٔ secrets خود تزریق کنید. ساخت image در این محیط بررسی نشده است.

## رفتار ارتباط با ترب

فقط مسیرهای GET مشخص روی `api.torob.com` مجازند. درخواست خرید، تماس با فروشنده، ورود یا دورزدن CAPTCHA ارسال نمی‌شود. لینک پیشنهاد فروش برای استفادهٔ کاربر برگردانده می‌شود و سرور آن را دنبال نمی‌کند.

در هر process حداکثر یک درخواست upstream هم‌زمان، با فاصلهٔ شروع حداقل ۵۰۰ میلی‌ثانیه و timeout دوازده‌ثانیه‌ای انجام می‌شود. خطای موقت شبکه یا 5xx حداکثر یک‌بار تکرار می‌شود. پاسخ‌های 401، 403 و 429 تکرار نمی‌شوند و مهلت انتظار به‌صورت `retry_after_seconds` برمی‌گردد. ظرفیت صف، cache و اندازهٔ پاسخ محدود است.

API وب ترب عمومی و مستندنشده است؛ تغییر ساختار با خطای `UPSTREAM_SCHEMA_CHANGED` گزارش می‌شود. خالی‌بودن واقعی نتایج با خطای شبکه یا مسدودشدن یکی نمی‌شود. پروژه به حساب کاربری ترب وصل نمی‌شود و log کاربردی از عبارت جست‌وجو ذخیره نمی‌کند؛ میزبان یا reverse proxy شما می‌تواند logging جداگانه داشته باشد. دادهٔ کوتاه‌مدت upstream، از جمله لینک‌های تولیدشدهٔ ترب، فقط در حافظه cache می‌شود.
